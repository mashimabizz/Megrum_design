## 2. 現行仕様の要約

Megrumは、K-POP、アニメ、イベントグッズ等の推し活グッズをユーザー同士で交換するためのアプリ。
運営者は取引当事者ではなく、在庫、wish、打診、ネゴ、取引チャット、証跡、評価、通報、ブロック、問い合わせ、課金機能を提供する。

初回リリース候補:

- 現地交換
- 在庫 / wish / 個別条件
- 打診 / 反対提案 / 合意 / 取引完了
- 取引チャット
- めぐり / グルーム / スポット掲示板
- 通報 / ブロック / 異議申し立て
- Premium / めぐりPlus / ブーストの有料機能候補
- AI機能候補（グッズ登録補助、画像解析、カテゴリ推定、不正利用検知等）

## 3. 原典からの主な変更点

| 論点 | 原典 | 現行ドラフト |
|---|---|---|
| 用語 | 原典作成時の提案・メッセージ系用語 | 打診、取引チャット等へ統一 |
| 投稿機能 | 原典作成時の旧投稿機能 | 現行MVPでは使わず、グルーム/掲示板として整理 |

## 4. 重点レビュー質問

### 4.1 現地交換と安全

1. 現在地共有、服装写真、到着状況を任意共有として扱う条項は十分か。
2. 位置情報・服装写真を取引終了後30日目安で削除又は非表示化する方針は妥当か。
3. 現地での事故、遅刻、キャンセル、危険行為について、運営者の責任分界は十分か。
4. 未成年者が利用する可能性に対して、保護者同意、機能制限、現地交換の注意喚起は十分か。

### 4.2 AI機能

1. 利用規約のAI機能条項として、AI出力の非保証、ユーザー確認責任、専門的判断を代替しない旨は十分か。
2. 外部AIサービスへ画像、投稿、取引情報、問い合わせ内容を送る場合、同意取得とプライバシーポリシー上の記載は十分か。
3. ユーザー入力を外部AIサービスの汎用モデル学習に利用させない方針を、どの文言で固定すべきか。
4. AIによる不正利用検知、通報補助、問い合わせ対応補助について、個人情報保護法上の説明や異議対応が必要か。
5. 初回リリースでは外部AI送信を避ける方針が望ましいか。

### 4.3 UGC / 通報 / ブロック / モデレーション

1. グルーム、掲示板、プロフィール、グッズ画像、取引チャットがUGCに当たる前提で、利用規約の投稿禁止事項は十分か。
2. 通報、ブロック、削除、非表示、アカウント制限の運営権限は十分か。
3. 通報者保護のため、対応結果の詳細を開示しない場合がある旨は十分か。
4. 虚偽通報や嫌がらせ通報への制限条項は十分か。
5. 著作権、商標権、肖像権、プライバシー権侵害の投稿に対する削除権限は十分か。

### 4.4 有料機能 / 特商法 / App Store課金

1. Premium、めぐりPlus、ブーストの表示価格候補を、特商法表記では「アプリ内又はApp Store表示価格を優先」としてよいか。
2. 代表者名、住所、電話番号を「請求があれば遅滞なく開示」とする表示は、現行運用で許容されるか。
3. 請求があった場合の回答期限、回答方法、本人確認の要否を運用上どう定めるべきか。
4. App Storeのアプリ内課金を使う場合、解約、返金、自動更新、退会との関係の文言は十分か。
5. ブーストが景品表示法、資金決済法、その他の規制上問題にならないか。

### 4.5 アカウント削除 / 退会 / 保存期間

1. 30日猶予で削除する設計は、規約・プライバシーポリシー上問題ないか。
2. 進行中取引、異議申し立て、未払い、法令対応がある場合に削除完了を保留する条項は十分か。
3. 削除後も保存する情報の範囲、目的、期間の記載は十分か。
4. Apple / Googleログイン連携解除、Sign in with Apple token revocation について、ユーザー向け説明を追加すべきか。
5. 有料サブスクリプションの解約が退会とは別である旨は十分か。

### 4.6 外国第三者提供 / 委託

1. Supabase、Apple、Google、Stripe、外部AI、分析/クラッシュ解析等が外国事業者の場合、プライバシーポリシーの記載で足りるか。
2. 外国にある第三者への提供について、国名、制度、保護措置をどこまで公開すべきか。
3. 委託と第三者提供の整理、本人同意の要否を確認したい。

### 4.7 古物営業法 / チケット / 権利物

1. ユーザー同士のグッズ交換プラットフォームとして、古物営業に該当しないための禁止事項や注意喚起は十分か。
2. チケット、抽選券、権利、金券等の禁止記載は十分か。
3. 反復継続的・営利目的の交換又は実質販売を制限する文言は十分か。
4. 盗品、偽造品、権利侵害品への対応条項は十分か。

## 8. 回答受領後の運用

- 回答原文はオーナー管理の安全な場所に保存する。
- 公開リポジトリには、回答の要点、判断、反映先だけを `notes/58_legal_review_response_tracker.md` へ記録する。
- Terms、Privacy、特商法、App Privacy、Review Notes、公開FAQ、アプリ内コピーに影響する回答は、反映漏れがないか台帳で確認する。
- 未反映又は要再確認の論点が残る場合、公開URL反映とApp Store提出を進めない。
