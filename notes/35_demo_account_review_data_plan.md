# 35. デモアカウント・審査用データ計画

> 目的：App Review、TestFlight内部確認、スクリーンショット撮影で使うアカウントと架空データを事前に定義する。
> コード変更なし。実アカウント作成、パスワード設定、DB投入は別作業で行う。

最終更新: 2026-05-31
ステータス: Draft v0.1（実アカウント未作成）

---

## 1. 重要方針

| 項目 | 方針 |
|---|---|
| 実パスワード | このリポジトリへ書かない |
| App Store Connect | Demo Account欄には実際のメールとパスワードを入力する |
| スクショ | 架空データだけを使う |
| 実在IP | 実在アーティスト、作品、キャラクター、公式画像は使わない |
| 個人情報 | 実住所、電話番号、個人メール、実名、座席番号を使わない |
| 有料機能 | 初回で隠す場合、デモアカウントにも有料権限を付けない |

デモアカウントのパスワードは、1Password等の安全な保管場所とApp Store ConnectのDemo Account欄だけに入れる。`notes/`、ソースコード、Issue、PR、Slack等には書かない。

---

## 2. 必要アカウント

最低2アカウント。可能なら3アカウントを用意する。

| 用途 | メール候補 | 役割 | App Reviewに渡すか | 備考 |
|---|---|---|---|---|
| 審査員ログイン用 | `reviewer+primary@megrum.jp` | メインユーザー | はい | App Store ConnectのDemo Accountへ入力 |
| 交換相手役 | `reviewer+partner@megrum.jp` | マッチ候補、取引相手 | いいえ | データ作成用。ログイン不要でもよい |
| 安全確認用 | `reviewer+safety@megrum.jp` | 通報/ブロック確認用 | 原則いいえ | 必要時だけ内部確認で使う |

未決定:
- `megrum.jp` ドメインでメールエイリアスを受信できるか
- Supabase Auth上で審査用メールが確認済み状態にできるか
- Apple/Googleログインだけでなく、メール/パスワードログインを審査用に出すか

- 位置情報ピンを出す場合、実住所や自宅・職場を想起させる地点を使わない。

## 7. 打診・取引データ

App Reviewでは、アカウントを2つ操作しなくても主要画面を見られるよう、既存データを用意しておく。

| 状態 | 内容 | 確認したい画面 |
|---|---|---|
| 下書き又は作成可能 | INV-01を譲り、PINV-01を受け取る | 打診作成 |
| `negotiating` | 反対提案が1件ある | ネゴ画面 |
| `agreed` | 待ち合わせが合意済み | 合意確認 |
| 取引中 | 取引チャットにサンプルメッセージあり | 取引チャット |
| 完了済み | 証跡と評価が完了 | 取引履歴 |

取引チャットのサンプル文:

```
ハナ: 東口広場の時計前にいます。
ソラ: ありがとうございます。14:10ごろ到着予定です。
ハナ: 服装は白いトートバッグです。
```

注意:
- 服装写真は実人物写真を使わない。
- 現在地共有はサンプル地点にする。
- 住所や電話番号をチャット内に入れない。

## 8. 個人情報露出防止データ

初回提出では、住所、電話番号、実名、座席番号などをデモデータに入れない。

| 項目 | 方針 |
|---|---|
| 住所 | 使わない |
| 電話番号 | 使わない |
| 実名 | 使わない |
| 座席番号 | 使わない |
| スクショ | 個人情報が見えない証跡を残す |

App Review Notesにも、デモ用の住所や電話番号は書かない。

## 9. UGC・安全確認データ

| 領域 | データ | 必須確認 |
|---|---|---|
| グルーム | サンプル会場の短文投稿 | 通報入口 |
| 掲示板 | 「東口広場、交換待ちの人が多めです」 | 通報入口 |
| プロフィール | 交換相手プロフィール | ブロック入口 |
| 取引チャット | サンプルメッセージ | 通報又は相談導線 |

不適切文言のサンプルを本番相当環境に入れる必要はない。審査では「入口がある」「運営に届く」「対応方針がある」を説明できればよい。

## 10. IAPデータ

初回提出で有料機能を隠す場合:
- デモアカウントへ有料権限を付けない。
- 購入画面、価格、Premium、めぐりPlus、ブースト導線が見えないことを確認する。
- Review Notesの有料機能段落を削る。

有料機能を出す場合:
- `notes/33_iap_product_setup_worksheet.md` の商品IDと一致させる。
- デモアカウントで購入画面、購入復元、権限反映を確認する。
- App Store ConnectのIAPを同じSubmissionへ含める。
- App PrivacyのPurchases回答と一致させる。

---

## 11. AIデータ

外部AIを初回提出で出さない場合:
- AIボタン、AI説明、AI処理中画面が見えないことを確認する。
- Review NotesのAI段落を削る。

外部AIを出す場合:
- 送信される情報、目的、学習利用の有無を画面上で説明する。
- AI結果は補助であり、ユーザーが修正できることを確認する。
- 個人情報や取引チャット全文を外部AIへ送らない設計にする。

## 12. App Review Notes差し込み文

```
Demo account:
Email: [App Store Connectにのみ入力]
Password: [App Store Connectにのみ入力]

The demo account includes sample inventory, Wish items, a matching partner profile, a proposal, negotiation, and a trade chat using fictional data only.
No real artist names, character names, addresses, phone numbers, or user personal data are included.
```

IAPを隠す場合:

```
Paid features are not enabled in this build.
```

外部AIを隠す場合:

```
External AI processing is not enabled in this build.
```
