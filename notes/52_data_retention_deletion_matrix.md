## 目的

Megrumで取得・保存するデータについて、保存理由、通常時の保持、アカウント削除時の扱い、例外的に保存する理由、実装確認ポイントを整理する。

この文書は内部の照合表であり、コード、DB、公開ページ、プライバシーポリシー本文は変更しない。

公開文面へ反映する前に、弁護士レビューと実DB/Storage/ログ実装の確認を行う。

## 1. 基本方針

個人情報保護委員会の情報では、個人データを利用する必要がなくなった場合には、遅滞なく消去するよう努めること、消去時は復元不可能な手段と委託先監督が重要であることが示されている。

Megrumの運用方針:
- 利用目的ごとに保存理由を分ける。
- 公開プロフィールや取引相手に見える情報は、アカウント削除時に原則非表示化又は削除する。
- 通報、異議申し立て、削除申出、送信防止措置、ブロック、評価、モデレーション、不正利用、会計、法令対応、監査に必要な情報は、必要な期間に限って分離保存する。
- 管理者権限、運営担当者の操作理由、変更前後の状態、IPアドレス、User-Agent、手動有料権限上書き、plan override、付与又は停止理由、運営通知等の監査ログは、通常のユーザー画面から切り離し、内部統制、セキュリティ、会計、法令対応、問い合わせ対応に必要な期間だけ保持する。
- Storage上の画像、公開URL、署名URL、サムネイル、端末キャッシュ、相手会員が保存した画像、外部サービス上のキャッシュは、DBレコード削除と同時に消えるとは限らない。公開文面では即時又は完全削除を保証しない。
- 共有シート又は外部SNSへ会員が共有したテキスト、生成画像、ハッシュタグ、リンク、画像メタデータ等は、共有先サービスの規約、公開範囲、保存、再共有、削除、広告利用、アクセス解析の仕様に従う。Megrum側の削除又は退会処理により、共有先サービス上の情報が当然に削除されるとは説明しない。
- 認証メール、パスワードリセット、Google OAuth、認証callback、custom URL scheme、通知linkPath、ID付きdeep linkは、メールアプリ、外部ブラウザ、OS、認証事業者、ログ、証跡又は端末履歴に残る場合がある。端末内Keychain等に保存されるAuth session、access token、refresh token、認証code、認証リンク、認証コードは秘密情報として扱い、公開証跡や問い合わせテンプレートに残さない。
- Web管理画面又は関連Webサイトのログイン状態維持には、Supabase Auth Cookie、Next.js proxy/middlewareによるsession refresh、認証callbackでのcode交換、password reset又はGoogle OAuth callbackが関係する。Cookie値、access token、refresh token、認証codeは秘密情報として扱い、ログ、スクリーンショット、公開証跡へ残さない。
- Swift DEBUG OSLog、Function logs、外部APIエラーdetail、管理者監査ログ、App Review証跡、サポート証跡には、token、secret、signed URL、画像URL、通知本文、通報本文、削除申出本文等が混入し得る。証跡化する場合は実値を貼らず、キー名、status、Pass/Fail、確認日時だけを残す。
- ログアウト時に端末内sessionを削除する経路があっても、他端末session、認証事業者側session、OSバックアップ、端末復元、ブラウザ履歴、メールアプリ、外部サービス上の履歴又はtokenが即時かつ完全に削除又は失効するとは説明しない。
- 現在地共有と服装写真は、取引終了後30日を目安に削除又は非表示化する運用を目標とする。ただし、2026-06-29時点の現行コードでは30日後の自動削除又は非表示ジョブは未確認であり、公開文面では即時削除、完全削除、自動削除完了を保証しない。
- 近距離公開、現地交換モード、待ち合わせ候補、グルーム、掲示板の作成位置、閲覧者位置、半径、距離、公開範囲は、表示、投稿、返信、通報、安全確認、監査のため保持され得る。1km/3km等の表示は削除単位、匿名化、秘匿化又は安全保証ではない。
- バックアップ、ログ、監査記録は、即時削除できない場合でも、合理的な期間後に削除又は匿名化する。

## 2. 用語

| 用語 | 内部定義 |
|---|---|
| 削除 | 不要なレコード、ファイル、表示情報を除くこと |
| 非表示化 | ユーザー画面や相手画面に表示しないこと。内部保存は残る場合がある |
| 匿名化 | 特定のユーザーに紐づけられない形へ加工すること |
| 消去 | 個人データとして使えない状態にすること。削除又は匿名化を含む |
| 分離保存 | 通常の画面表示や検索から切り離し、法令・安全・監査目的だけで保持すること |

## 4. アカウント削除時の処理順

現行実装で確認済み:

1. 設定画面から退会申請を開始する。
2. 進行中の取引（`sent` / `negotiating` / `agreement_one_side` / `agreed`）がある場合は申請を拒否する。
3. 退会理由と任意メモを受け付ける。
4. `users.account_status='deletion_requested'` とし、削除申請中状態として扱う。現行コード確認では、申請成功後に全画面を強制ログアウト又は全機能ブロックへ切り替える処理までは未確認。
5. `account_deletion_requests` に申請日時、削除予定日、理由、任意メモ、申請状態を保存する。

提出前に実装又は運用確認が必要:

6. 通常画面・相手画面・検索結果から対象ユーザーが確実に非表示又は利用制限されることを実機で確認する。
7. 認証情報、APNs token、プロフィール、在庫、wish、公開投稿、画像を削除、匿名化又は無効化する手順を決める。APNs tokenはログアウト時及びAPNs失効応答時の `revoked_at` 更新経路はあるが、退会申請/削除完了時に全端末tokenへ処理が及ぶかは未確認。過去又は別環境でExpo Pushを使う場合はExpo tokenも別途処理対象にする。
8. 通報、異議、会計、サポート、監査に必要な情報を分離保存する。
9. Sign in with Apple token revoke、Google連携解除、Supabase Auth削除の要否と手順を決める。
10. バックアップとログのローテーション期限を記録する。
11. 管理者監査ログ、手動権限上書き、運営通知、Webhook又は決済同期ログを退会後も残す範囲、保持期間、閲覧権限を決める。
12. 完了通知、手動処理記録又は問い合わせ回答の運用を決める。

注意: 2026-06-29時点のコード確認では、30日後の実削除ジョブ、削除申請キャンセル、ログイン復旧、削除完了通知は未確認。公開文面では、削除予定日を処理予定の目安として扱う。

## 7. 公開文面へ反映する候補

公開前に法務確認する候補:

- 個人情報は利用目的の達成に必要な範囲で保存する。
- 利用する必要がなくなった個人データは、合理的な期間内に削除又は匿名化する。
- 現在地共有と服装写真は、取引終了後30日を目安に削除又は非表示化する運用を目標とする。ただし、現行コードでは30日後の自動削除又は非表示ジョブは未確認であり、即時削除、完全削除、自動削除完了を保証しない。
- 現地交換モード、待ち合わせ候補、グルーム、掲示板では、現在地、作成時の緯度経度、閲覧者の緯度経度、半径、距離、公開範囲、投稿時刻、返信可否を扱うことがある。近く、1km圏内、3km圏内、同じスポット、同じ都道府県等は表示/投稿/返信条件であり、匿名化、安全確認、所在確認、本人確認又は推測防止を保証しない。
- 顔特徴量、画像特徴量、顔候補付け結果、補正履歴、学習データ追加可否は、グッズ登録補助、誤判定防止、問い合わせ対応、権利侵害対応、監査のために必要な期間だけ保存し、不要になった場合は削除、匿名化又は無効化する。`member_face_profiles` にembedding又はsource image URLを保存する場合は、同意記録、読み取り範囲、削除/利用停止、外部送信の有無を別途確認する。
- 外部AIへ送信した画像、画像URL、推し文脈、既存候補、出力候補、ログは、機能提供、安全確保、濫用監視、障害調査、問い合わせ対応、監査その他必要な目的のため合理的に必要な期間保存されることがある。外部AIサービス側の保持期間、削除可否、web search由来情報の扱いは、当該外部サービスの仕様又は契約条件に従う。

## 8. No-Go

- プライバシーポリシーに保存期間の目安を書いたのに実装で削除できない。
- アカウント削除後も公開プロフィール、在庫、wish、画像、取引相手画面に個人情報が残る。
- 30日後の実削除ジョブ、申請取消、ログイン復旧、削除完了通知が未確認なのに、公開ページやReview Notesで「30日後に必ず削除」「ログインで復旧可能」と説明する。
- APNs tokenを残して削除済みユーザーへ通知が届く。過去又は別環境でExpo Pushを使う場合はExpo push tokenも同様に扱う。ログアウト時やAPNs失効応答時のrevoke経路があっても、退会申請/削除完了との連動を未確認のまま保証しない。
- 通知本文に正確な位置、住所、銀行口座、内部ID、不要な個人情報又はセンシティブなチャット本文が含まれる。
- 現地交換モードOFF、近距離投稿削除、アカウント削除又は位置情報権限OFFにより、過去の現在地共有、待ち合わせ候補、グルーム/掲示板の作成座標、閲覧者座標、通知、相手保存、通報証跡、監査ログ、バックアップが即時完全削除されるように説明している。
- 近く、1km圏内、3km圏内、同じスポット又は同じ都道府県を、匿名化、安全確認、本人確認、所在確認、ストーカー防止又は推測防止として説明している。
- 郵送先情報、電話番号、銀行口座、PayPay、現金交換、金額指定又は成立後支払い情報スナップショットを扱うのに、App PrivacyのContact Info / Financial Info、参加者限定表示、目的外利用禁止、外部決済サービス非関与、削除後の例外保持が説明できない。
- Megrumが住所確認、本人確認、配送保証、送金、返金、決済代行、収納代行、エスクロー、口座名義確認、支払能力確認、外部アカウント/リンク/QRコード/外部ID/残高/送金可否/受領可否の確認を行うように説明している。
- 生年月日又は年齢表示が残っているのに、削除/匿名化、相手画面の非表示、App Privacy、Age Rating、公開説明が未確認。
- 自己申告年齢しかないのに、年齢確認済み、本人確認済み、保護者同意確認済みと説明する。
- OSのロック画面、通知センター、連携端末、通知プレビューに出る内容とPrivacy/FAQ/アプリ内コピーの説明が矛盾している。
- Storage画像やバックアップの扱いが未確認。
- public bucketに入る画像、private bucketに入る画像、signed URL期限、URL再共有、削除時のURL無効化を説明できない。
- `meguri-board-media` のauthenticated selectが掲示板表示範囲、block、非表示、削除、通報対応と矛盾する可能性を未確認。
- 写真のEXIF、GPS位置情報、撮影日時、端末情報などのメタデータが残る経路と削除可否が未確認。
- 共有シート又は外部SNS共有後の投稿、キャッシュ、ログ、再共有、削除、広告利用、アクセス解析、画像メタデータ利用が共有先サービスの仕様に従うことを説明できない。
- 外部画像URL、画像ホスト/CDN、端末キャッシュ、第三者サービス側の保持/削除仕様が未確認。
- 外部サービス側の削除/保持仕様が未確認のまま外部AIや分析SDKを出す。OpenAIへ画像又は画像URLを送る導線が見えるのに、web_search、保持、濫用監視ログ、削除可否、学習利用を説明していない状態もNo-Go。
- 顔特徴量又は画像特徴量を扱うのに、削除/無効化、同意撤回、外部送信、App Privacy Sensitive Info回答、`member_face_profiles` の読み取り範囲、学習データ追加可否が未確認。
- 通報者保護が必要な記録を、対象ユーザーへ不用意に開示する。
- 評価、通報、異議申し立て、削除申出、送信防止措置、ブロック、モデレーション記録があるのに、保持期間、分離保存、削除後の例外保持、App Privacy分類が未確認。
- ブロックや退会により、過去の取引、チャット、証跡、評価、通報、異議申し立て、監査記録が当然に削除されるように公開文面で説明している。
- 管理者操作ログのbefore/after stateに個人情報、通報内容、課金/権限情報、通知本文が含まれるのに、閲覧権限、保持期間、退会後保持、漏えい時対応が未確認。
